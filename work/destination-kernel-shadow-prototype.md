# Destination-kernel shadow prototype

Work-only observational stage. It does not reuse a score, skip a forecast,
change a policy call, alter search limits or modify the current core files.
Tactical control is frozen DLL86 (`ef274591d`); the one diagnostic-category
mapping uses frozen87 (`2bdba7c058`). The indexed-store candidate must be
adopted or rejected before this stage is mechanically rebased and source-bound
again. Do not apply both experimental patches together.

The question is whether hypothetical child states repeatedly evaluate the
same destination danger/stack graph. A large incremental evaluator is worth
building only if real conservative overlap and its descriptor cost support
that direction. This observer provides that evidence while the complete
original kernels continue to execute and drive the game.

## Captured footprint

It observes `GetUnitDangerForPlot` and `ScoreStackPositionMembers`, separately.
For a stable1/64 cohort selected by kernel kind, owner, actor ID and destination
plot, it captures the existing full scalar forecast keys in their original
call order, including hits. It also captures:

- Direct actor/candidate native identity, owner/team, live HP/max HP, domain,
  combat/cargo/delayed/ranged/defense/anti-cavalry and terrain-damage fields.
- The full raw input wound ledger, preserving its order, zeros and duplicates.
- Exact ordered source owner/ID rows, improvement/fog/flat hazards and city
  protection/HP through the existing const cache descriptor.
- The original final kernel result. Unit-danger sentinel conversion is included.

The source reader never refreshes before the original kernel. Dirty or
unsupported contexts are censored. A selected observation is completed only
after unchanged owner/context/sampling epoch/revision/scene, source descriptors
and participant fields are revalidated. Exceptions do not complete a result.
Busy/nested/foreign observations cannot overwrite another frame's scratch.

**This is an observed footprint, not a certified complete dependency schema.**
Equality of key sequences/direct fields/results is an opportunity to investigate,
not permission to substitute a result. Deeper helper inputs, immutable XML
assumptions and every state mutation still need a production reuse proof.
The fixture deliberately changes an unrecorded configurable join bonus and
requires a detected result mismatch; it demonstrates that this instrument can
falsify its hypothesis instead of silently calling it complete.

The outer frame deliberately records the **entire**
`position.GetUnitDamageDealt()` ledger. Existing scalar danger keys project
enemy wounds to sources that can affect the queried destination. Consequently,
an unrelated enemy wound can split this observer's group even when its original
scalar-key sequence and destination kernel remain reusable. Low repeats here
cannot alone reject incremental evaluation or demonstrate that every input was
affected. They are a conservative coverage floor. If native data warrants it,
a separate key-sequence-only grouping could quantify that bias; it would be
weaker opportunity evidence and would still not certify complete dependencies.

## State relationships and bounds

Native position pointers, generation and getID are insufficient identity:
temporary previews and rejected slots can be reconstructed with the same tuple.
A diagnostic-only monotonic incarnation registry is updated at scratch/parent
initialization, accepted assignment and primary damage/heal mutation points.
`SameIncarnation` and `CrossIncarnation` describe that covered-mutation token;
they do not certify equality/inequality of every logical state field. The
`ParentAtMutation` relation compares the parent token captured at that hook.
Unhooked initial pruning/direct mutations require further audit before any
stronger state claims or active reuse.

There are128 metadata groups of at most2048 integer words,8192 incarnation
slots, and a maximum64 probes per registry lookup. Exhaustion/collisions beyond
that bound produce unknown relations rather than an8192-step scan. Full word
equality follows hashing. Group FIFO eviction and oversized/dirty/invalidated
observations censor repeats; counts are lower-bound observations of the retained
cohort, never totals extrapolated by multiplying64. Metadata remains below3MiB
and does not compete with forecast results, keys, queues or capacities.

The existing tactical sampling switch controls activation; default-off frame
constructor/Finish and danger-input hooks are inline pointer gates. Active
work is delegated to cold methods. No new gameplay/XML numeric setting or UI
button is introduced.

## Reading the row

One `PLAN_KERNEL_PROBE` performance-category row is emitted per sampled PLAN
session. Unit/stack fields are separate. Counts expose calls/selection,
completed footprints/groups/repeats, same/cross incarnation, parent-at-mutation,
unknown relations/mismatches, zero-forecast-key calls, key visits and actual
original scalar hits/misses/outcome builds.

`KernelTicks` is inclusive same-thread wall time and contains `PrepInsideTicks`
from the key-input observer. `PrepOutsideTicks` covers constructor/Finish
metadata work outside that interval. Those three values are not additive;
subtracting all preparation from KernelTicks would be wrong. Mutation-hook
and session-allocation overhead are not covered by the frame preparation
timers. Frequency0 or failed/zero tick endpoints means unknown timing, not
zero CPU. No number predicts saved seconds.

The existing global4096-row diagnostic budget still applies. Drops or missing
rows make the report incomplete; zero retained rows means missing measurement,
not zero opportunities. The new category should be excluded from legacy
first-event timing anchors before native analysis. All-event views should
retain it. Existing policy/city/combat records remain separate evidence;
signature equality alone does not prove their invocation behavior.

## Offline reader

The work-only reader is ready for the frozen version1 wire format:

```text
python -B work/test-kernel-probe-profile.py
python -B work/profile-kernel-probes.py <native-segment-folder> --run <exact-native-run> --turn 253 --map-width 88 --output <report.json>
```

`--turn`, `--player` and `--map-width` are optional. Map width must be independently
verified. The reader uses the existing canonical native segment loader from
`work/profile-turn-phases.py` and the identity/schema services from
`work/profile-plan-samples.py` and `work/profile-packet-probes.py`. Those files
are its prerequisites. The light self-test also binds its field names and
semantics marker to `work/destination-kernel-probe-fragment.cpp`.

Current reader result: **83 checks, zero failures**, in about0.2 seconds, with
no compiler, game or benchmark. Its synthetic worst numeric wire is1949 bytes,
within the existing3072-byte message bound. Evidence is
`work/kernel-probe-profile-regression/result.json`.

The report keeps unit-danger and stack-score counts separate, reports result
mismatches, covered-mutation token relationships and unknown registry relations,
and exposes FIFO eviction/clear, oversized/source-unavailable/invalidated and
row-budget censorship. Bytes are per-PLAN maxima. Each timing row uses its own
QPC frequency; kernel and inside/outside preparation clocks remain separate and
nonadditive. Frequency0, zero-resolution called work and no complete frames are
unknown timing. No stride scaling, predicted saved simulation count or saved
seconds appears in the report.

`PLAN_SAMPLE` joins require exact turn/player/target/thread/serial. Legacy
PLAN/PERF are only bounded adjacency candidates; the reader may skip one valid
`PLAN_PACKET_PROBE` footer with that exact identity, and never searches backward
past arbitrary intervening events. Duplicate identities, duplicate wire fields,
truncated messages and unsupported schema rows are excluded explicitly. No
valid probe rows means unknown opportunities. The whole-ledger coverage bias
and incomplete dependency certification are repeated in every report.

This parser does not adopt or rebase the frozen probe. Native evidence remains
pending; the current indexed-store trial has not completed quiet validation.
