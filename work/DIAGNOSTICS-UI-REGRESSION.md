# Built-in diagnostics controls: source checkpoint

The Game Lua bindings expose the native diagnostics service through GetStackingDiagnosticsLevel, SetStackingDiagnosticsLevel and GetStackingDiagnosticsStatus. The setter accepts only numeric values equal to0/1/2 and returns the resulting level. Registration/declarations and argument position1 match CvLuaStaticInstance. The wrapper issues no network/gameplay order or RNG call. Core logging/default/reset behavior is owned by CvStackingDiagnostics and is not implemented by these UI changes.

The registered StackPanel add-in supplies a standalone **Diagnostics** button near the top center of the map. Its independent, initially hidden panel offers Off/Summary/Verbose, current native status/path/error, and the XML-default reopening notice. Access does not depend on selection, stack size or UIStackEnabled. Opening it cancels an active stack-target selection before showing the panel, but issues no unit orders. Existing roster layout and movement code remain unchanged. Closing/city-screen/player changes hide the panel; the button hides in the city screen or when native APIs are unavailable.

Validation: work/test-diagnostics-ui.py executes the complete current StackPanel Lua in Lua5.1 with deterministic UI/native-service stubs: 43 checks pass for default-off/no mutation on load, no-selection access, levels, current-state/error/path display, dynamic layout, reopening default notice, external state readback, Escape/close/city-screen/player change and missing APIs. It also executes the actual EUI menu consumer to cover empty-art filtering and callback order. The original 37-check implementation missed these EUI access failures, which were found in the live game and corrected. XML parsing and source wrapper declarations/registration/exact-level guard checks pass. Exact hashes are in work/diagnostics-ui-regression/result.json.

The existing work/test-stack-ui.py regression also passes its roster, capacity/HP/moves, selected row, preview reasons, protector/fog warning, frozen membership, result counts, visible-only badges, combat summary, cargo, late-arrival and stationary-dirty refresh checks. Only input-handler and event-removal mock support were added to that scaffold.

The coordinator subsequently verified the standalone button and panel in the actual DX11 game, including observer mode, all three levels, readable native status/path, Escape and Close. Off/On continued the same native log ring, and a fresh load restored Off. See [live evidence](NATIVE-DIAGNOSTICS-LIVE-20260927.md) for the separate runtime tests and their exact DLL identity.
