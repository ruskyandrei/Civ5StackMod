# Reuse an existing scalar key within one parent batch

The candidate can skip repeated key preparation and lookup only when the
original scalar entry is still resident. It stores a key certificate, not a
second danger result. Certificates are captured during existing full-key hits
from qualified GetUnitDanger arrivals; no extra lookup or unqueried admission
is added. Generic/full/solo/foreign/nested/private requests use the original path.

The parent preparation witness fixes ordered roster membership and first-match
health. Current fixed key words, city protection and canonical order are still
read. The original source-projected enemy damage builder runs once, including
aliases, duplicates, zero filtering, negative city IDs and NULL-source fallback.
The original final Context/revision/scene gate precedes exact suffix comparison
and a checked resident handle. Failure reconstructs the complete original key
with the original growth/admission capacity and follows the existing miss helper.

This proves equality to the original key lookup. It does not strengthen the
original key into a complete freshly evaluated danger dependency contract.
Sampling forces complete serialization for comparable diagnostic footprints.
One honest scalar hit is counted when a live resident entry supplies the result.
The added counters report certificates and preparation activity without extra
rows;47 formatter arguments fit a conservative1,336-byte bound below2,048.

Handles validate table lifetime, bounds, queued publication and insertion
generation before reading slots. Eviction, clear, release, reinitialization and
wrap reject stale handles without new forecast clears or budget changes. The
owning global table has process lifetime; tokens cannot cross object destruction.
Certificate capacities share the existing optional parent payload budget.
Slot storage grows24,004 bytes at6,001 slots, the table12 bytes, parent cells
11,220 fixed bytes, plus a128-word optional prefix scratch and small fields.
This limit only disables the shortcut; larger keys retain original evaluation.

The source-bound oracle passes64,347 checks, including real hash collision,
allocation failure, terminal lifetime wrap, eviction, dirty refresh and fallback
cases. A warm certificate dirtied inside the source getter is rejected by the
mandatory final Context; the leaf computes once and nothing is admitted.
Both complete Tactical source and thirteen unchanged dependencies are
bound; numerical/native services use deterministic substitutes. Projector and
outlined miss helper are byte-identical. Stock CRT allocation is callback-free
in this contract; arbitrary allocator callbacks reclaiming the whole owner scope
are excluded. Normal bad_alloc and engine invalidation remain supported.

The first native replay preserves all699 ordered semantic records, both nonempty
world censuses and all34 legacy non-timing cache fields across455 searches.
The physical forecast estimate increases by24,016 bytes per row; it excludes
parent/certificate metadata. Native caller locals grow from64 to92 bytes,
with the2,212-byte miss helper and GS/EH retained.

This version does not demonstrate a speedup: T252 takes32.469s (PLAN9.504s)
and T25359.156s (PLAN34.595s), versus DLL96's31.266/57.359s
(PLAN8.802/32.827s). One pair is noisy, but this regression warrants revision.
T253 records7,224,875 resident hits (34.22% of danger hits),8,665,323 captures
and9,526,513 rejects. Captures are events, not unique certificates; rejection
reasons are not recorded. The counters do not establish seconds saved.
Evidence is `work/test-runs/perf-d97-resident-key-off-251-255`.

Reproduction sources, detailed proof and independent review are saved under
`work/resident-key-elision*` and `work/resident-scalar-handles-stage.py`.

The allocation-free slot-key revision also preserves all699 records, both
censuses,34 legacy fields and all five added counters in455 searches. It takes
32.391/60.250s on T252/253 (PLAN9.287/34.484s). These first pairs do not establish
a benefit over96. Both resident revisions were therefore removed from production;
the exact96 Tactical source is restored. Reproduction and rejected-candidate
evidence remain available. The slot-key implementation and its64,358-check
oracle are documented in `work/resident-slot-key.md`.
