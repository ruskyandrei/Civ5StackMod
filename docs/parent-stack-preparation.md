# Shared preparation within one tactical parent

This candidate reuses ordered friendly rosters and first-match virtual health
data through one parent's const preferred-unit batch. Each destination is built
once; arriving units and their exact damage override are then applied in the
original order. Full forecast keys, numerical kernels, cache admission and FIFO
policy still execute as before. No danger result is retained by this view.

The existing query's fresh owned scratch loan admits preparation reuse. Only
the parent and an explicitly witnessed GetNextPosition preview with the same
five CoW roster/stat containers qualify. Enemy damage stays dynamic. Private,
foreign, nested, changed-container, revision or scene paths use the original
builder. The lexical view ends before child expansion. Native skipped getters
are field/container reads without event seams in this locked batch; this is
not a general immutable-state certificate for arbitrary callers.

The work-only actual-source oracle passes295,462 checks, including exact keys,
scratch capacities, Context counts, scalar hit/miss graphs, duplicates, sentinel
clamping, first-match health, EFD previews, fallbacks, allocation failure and
exception teardown. Both complete changed files and sixteen unchanged numerical
and native dependencies are bound before production verification. Numerical
leaf/backend substitutes in this fixture check preparation and traffic;
native replay remains required to validate real gameplay and speed.

Fixed VC9 x86 metadata is16,332 bytes. Retained dynamic capacity is bounded by
the existing forecast payload ceiling,624,000 bytes in the tested setup;
temporary growth can exceed it before rejection. Exact incremental accounting
avoids scanning255 cells on every destination build. Warmed preparation adds no
Context or interlocked epoch call. Allocation/cap failure releases optional
payload before the original builder retries, and search teardown releases it.
The existing forecast estimatedBytes statistic excludes this separate storage.

Reproduction tools are `work/prepare-parent-stack-preparation.py`,
`work/test-parent-stack-preparation.py --production`, and the guarded
`work/apply-parent-stack-preparation.py`. Template and independent review are
saved alongside the work artifacts. Native benefit is currently unmeasured.
The target remains below30 seconds per late-game turn.
